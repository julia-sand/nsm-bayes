# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Changed

- **Breaking change (API):** `nsm_bayes.inference.slice_sampler` is removed (`run_multivariate_slice_sampler_tuned`, `log_posterior_wrapper` and the private 1-D slice helpers); importing the module no longer works. `GeneralPosterior.sample` now builds `sbi.inference.MCMCPosterior` directly: method `"slice_np_vectorized"`, the potential is `GeneralPosterior._potential` bound with `functools.partial` (batched log-posterior over the chain states, `beta` keyword-bound), `proposal` is the prior, and the sampler settings come from the `mcmc` dict. The `types.SimpleNamespace` settings wrapper (`GeneralPosterior._sampler_settings`) is gone with it.
- **Behaviour change:** the generalised (normflow) posterior is sampled with sbi's coordinate-wise vectorised slice sampler instead of the in-repo random-direction slice sampler with EMA bracket-width tuning, so `samples_sm` — and anything derived from it (`posterior_mean`, `posterior_covariance`, and, whenever the bootstrap draws differ, the calibrated `beta`) — differ for a fixed seed. `num_posterior_samples` is now the total number of draws across all chains (previously per chain, and a smaller count when `thin > 1`); the calibration pool size `M` is exactly `num_posterior_samples` regardless of `mcmc.num_chains`, so the ESS-refresh threshold `ess_threshold * M` no longer scales with the number of chains. The NLE baseline (`samples_nle_mis`), which already used sbi MCMC, is unchanged.
- **Breaking change (API):** `nsm_bayes.models.general.mcmc_settings.MCMCSettings` is removed. `GeneralModel` now takes `(prior, mcmc: Mapping[str, Any], num_samples: int, density_estimator="maf")` and `GeneralPosterior` takes `mcmc: Mapping[str, Any]` and `num_samples: int` (both required, no defaults) instead of the settings dataclass. Callers pass the plain dict of sampler settings — the composed `cfg.mcmc` converted with `OmegaConf.to_container(..., resolve=True)` — plus `int(cfg.num_posterior_samples)`; `run_normflow_methods` does this conversion. `GeneralModel.sample_nle_posterior` forwards the dict as `**kwargs` to sbi's posterior `sample` (the previously hard-coded `init_strategy="proposal"` now comes from `mcmc["init_strategy"]`), and `GeneralPosterior.sample` still calls `run_multivariate_slice_sampler_tuned`, wrapping the dict in a `types.SimpleNamespace` with the same attribute values it always read.
- **Breaking change (config/CLI):** the top-level `num_chains`, `warmup_steps` and `thin` keys moved under a new `mcmc:` block in `configs/_base.yaml` (`num_chains`, `warmup_steps`, `thin`, and a new `init_strategy`, default `"proposal"`); `num_posterior_samples` stays top-level with a base default of 500 (turin keeps its own 1000). Command-line overrides move with the keys, e.g. `num_chains=4` is now `mcmc.num_chains=4`. No experiment differs from the base `mcmc:` values, so the per-experiment YAMLs dropped the old keys with no overrides added. Results are bit-identical for a fixed seed: both samplers receive exactly the settings they received before.
- `GeneralModel` now builds its trainer from `sbi.inference.NLE_A` instead of the deprecated `SNLE` alias (the same class in sbi 0.27, so results are bit-identical); this silences the sbi deprecation `FutureWarning` and drops the last use of a name removed in sbi 0.28. The module attribute is `normflow.NLE_A` now (was `normflow.SNLE`).
- The chi-square critical value in `ConjugatePosterior.estimate_coverage` (and the test stub mirroring it) is now computed by a new `nsm_bayes.utils.statistics.chi2_ppf` — a float64 bisection on `torch.distributions.Chi2`'s CDF, which torch provides without an inverse CDF — instead of `scipy.stats.chi2.ppf`. Values agree with scipy's to ~1e-12, so results are unchanged at any practical tolerance. **Behaviour change (negligible):** the critical value used in the coverage indicator is a bisection root rather than scipy's, differing at the 1e-12 level; a bootstrap sample would have to land inside that sliver for any downstream result to differ. The `scipy` dependency was dropped from `pyproject.toml` as the chi-square import was its last use (sbi's own dependency on scipy is unaffected).
- `GeneralPosterior` and `ConjugatePosterior` now store the calibration's miscoverage level and bootstrap count as `alpha` (float) and `B` (int) instance attributes, set at the start of `prepare_calibration` and documented in the class docstrings (`None` until it has been called). Purely additive; no numerical behaviour changes.
- `GeneralPosterior.estimate_coverage` and `ConjugatePosterior.estimate_coverage` now read `alpha` and `B` from the posterior's own state (set by `prepare_calibration`) instead of accepting them as parameters. The `alpha` and `B` arguments were removed from both `estimate_coverage` signatures; callers that already go through `calibrate_beta` (which calls `prepare_calibration` first) are unaffected. `beta_bo_calibration.optimize_beta_ei`, which calls `estimate_coverage` directly, now works without passing `alpha`/`B` explicitly.
- `ConjugatePosterior.estimate_coverage` no longer accepts an `x_obs` argument: it bootstraps the rows of the observed data cached by `prepare_calibration` (`self._calib_x_obs` / `self._calib_x_n` / `self._calib_terms`) instead. `prepare_calibration` must be called first (it already was in the `calibrate_beta` workflow); the previous behaviour of accepting a *different* `x_obs` and erroring on mismatch is gone — call `prepare_calibration` again for new data. **Behaviour change**: old `estimate_coverage(beta, x_obs, ...)` with an `x_obs` matching the calibration data is now `estimate_coverage(beta, ...)` and gives identical results; passing a different `x_obs` used to raise `ValueError`, now the argument does not exist.
- `GeneralPosterior.estimate_coverage` no longer accepts its unused `x_obs=None` argument either: the general method always uses the `x_obs` it was constructed with, so the argument was redundant. Callers going through `calibrate_beta` are unaffected (the shared call site never passed it); `GeneralPosterior.prepare_calibration` keeps its `x_obs=None` parameter only so both posterior classes share one flat signature. No numerical behaviour changes.
- The distribution name in `pyproject.toml` is now `nsm-bayes` instead of `nsm_bayes`. PEP 508 normalizes both to the same name, so pip/uv resolution, existing installs and the `import nsm_bayes` import name are all unaffected; this only makes the canonical (dashed) form the declared one, ready for PyPI.
- `pyproject.toml`: the `sbi` dependency is now `>=0.27,<0.28` instead of `>=0.23.0,<0.28`. The code targets sbi 0.27 `log_prob` semantics, so the old lower bound admitted versions that would not work; fresh installs were already resolving to 0.27.
- `pyproject.toml`: the wheel no longer ships `nsm_bayes.experiments.test_data` (excluded via `[tool.setuptools.packages.find]`). The subpackage is dev-only data-bundle generation that references the repo-root `configs/` directory, so it is useless from an installed wheel; it remains in the source tree and is unaffected for editable installs.
- `pyproject.toml` dependencies: added `botorch>=0.10` (imported by `nsm_bayes.inference.beta_bo_calibration`; it also installs `gpytorch`, which that module uses directly) and `matplotlib>=3.7` (imported by `nsm_bayes.viz.plot_gnk`), and dropped `tqdm` (not imported anywhere in `src/`, `scripts/` or `tests/`). `requires-python` is now `>=3.10,<3.13`: on 3.13 `nflows`/`antlr` fail to build.
- `pyproject.toml` dependencies: the `numpy` pin is now `>=1.26.4` (no upper bound) instead of `>=1.26.4,<2`, and the `botorch` lower bound is now `>=0.11` instead of `>=0.10`. Neither was a hard requirement of any dependency in the stack (torch, sbi, nflows, zuko, gpytorch, botorch), and every one of them is numpy-2 compatible — the `<2` cap was a self-imposed precaution. **Behaviour change (none expected):** existing installs already resolve to numpy 1.x and keep working; fresh installs may now pick numpy 2.x, which the full test suite passes against. The `botorch>=0.11` floor only guards fresh installs: 0.11+ is the first line guaranteed to work with numpy 2 (installed 0.18.1 is unaffected).
- `pyproject.toml` dependencies: the upper caps on `torch`, `hydra-core`, `scikit-learn` and `omegaconf` were removed (now `torch>=2.2.0`, `hydra-core>=1.3.2`, `scikit-learn>=1.4.2`, `omegaconf>=2.3`). None of the removed majors (torch 3.x, hydra 2.x, sklearn 2.x, omegaconf 3.x) has been released, so the caps only constrained future fresh installs; existing installs resolve to the same versions. No code or numerical changes.

### Changed

- **Behaviour change:** `_iterative_loop` in `nsm_bayes.inference.beta_calibration_loop` no longer refreshes the MCMC pool on the final calibration iteration (`t == n_iterations - 1`). The pool drawn on the last iteration has no downstream consumer (calibration ends immediately after), so the previous refresh was wasted MCMC cost. All earlier iterations are unaffected, so results for a fixed seed are bit-identical whenever the ESS-gated refresh is not triggered on the final iteration; when it *was* triggered, only the unused final pool draw is skipped and the returned `log_beta` is unchanged. Covered by `tests/test_units.py::test_pool_not_refreshed_on_final_iteration`.
- **Breaking change:** `nsm_bayes.inference.beta_calibration_loop.calibrate_beta` now validates its keyword arguments strictly: any keyword not in the signature (including misspellings such as `init_beta`, `beta_minimum` or `num_bootstrap`) raises `TypeError` immediately, instead of being silently ignored (the old special-case `TypeError`s for `beta_init` / `step_schedule` are unchanged). No in-repo caller passes such keywords, so experiment results are bit-identical. Covered by `tests/test_units.py::test_unknown_kwargs_raise_type_error`.

### Added

- `nsm_bayes.inference.beta_bo_calibration.optimize_beta_bo(betas, coverages, target_coverage=..., beta_min=...)`: Bayesian-optimisation beta calibration via a GP on a coverage grid. Fits a `Matern`-kernel `GaussianProcessRegressor` to pre-computed `(log beta, coverage)` pairs and returns the scalar `beta` where the GP mean crosses the target coverage (clamped to `beta_min`). Unit-tested in `tests/test_units.py` (5 tests: crossing recovery, no-crossing fallback, `beta_min` floor, input validation, determinism).
- `nsm_bayes.inference.beta_calibration_loop.calibrate_beta(posterior, beta_init, ...)`: a single unified beta calibrator that drives the shared stochastic-approximation loop over `log beta` for both methods. The method-specific work moved into the posterior classes, which now both expose `prepare_calibration(...)` (caches the NSM point estimate `theta_hat`; for the general method also draws and caches the base MCMC pool at `beta_init` and its per-observation losses) and `estimate_coverage(...)` (importance-reweighted coverage with the ESS-gated pool refresh for :class:`GeneralPosterior`; closed-form bootstrap coverage for :class:`ConjugatePosterior`). Both share one flat signature — each class ignores the arguments its method does not need. `run_normflow_methods` and `run_conjugate_method` now call this single entry point.
- The `on_update` callback of the shared SA loop is gone; the ESS-gated pool refresh now happens in the calibration loop (`_iterative_loop`) when the mean effective sample size returned by `estimate_coverage` falls below `ess_threshold * M`.  `GeneralPosterior` gains a public `refresh_pool(beta)` method that redraws the MCMC pool at `beta`, recomputes the per-observation losses, and updates `beta_base` so subsequent importance-reweighting calls use the refreshed pool as reference; `estimate_coverage` itself no longer mutates the pool (it returns the pool size so the caller can make the refresh decision).  The refresh beta is a small local step around the current coverage (fixed rate `k_t = 10 / (10 + B)`, clamped to `±max_log_step` and floored at `beta_min`), mirroring the historical behaviour of the internal refresh.
- `ConjugatePosterior` now prints nothing during calibration: the `tqdm` bar and the per-iteration / final prints of the old `calibrate_beta_gpc` were dropped (logging goes through `logging.getLogger` instead).
- The library is now licensed under the MIT licence: a `LICENSE` file was added and `pyproject.toml` declares `license = {text = "MIT"}` so pip/PyPI metadata carries it. No code or numerical changes.

### Fixed

- Docstrings: corrected several inaccurate or stale docstrings (no behavioural change). The `Returns` block of `nsm_bayes.inference.beta_calibration_loop.calibrate_beta` now matches the keys it actually returns (`"betas"`, `"coverages"`, `"ess"` always; `"grid"`, `"initial_beta"`, `"slope"`, `"bracket"` only with an array `initial_beta`; the final bracket in `log(beta)` units). `nsm_bayes.inference.beta_bo_calibration.optimize_beta_bisection` and `optimize_beta_bo` no longer claim to return a coverage; the `posterior=None` branch of `optimize_beta_bo` is documented as delegating to `optimize_beta_bisection` without forwarding `target_coverage`/`beta_min`. The `step_gpc` docstring drops its stale "Bit-identical to the loop's inlined update" claim, and `GeneralModel.log_prob` drops a reference to a `None` default that `theta_vec` does not have.
- Docstrings: fixed five broken Sphinx cross-references to the removed module `nsm_bayes.inference.calibrate_beta` (deleted when the calibrators were merged), now pointing at `nsm_bayes.inference.beta_calibration_loop.calibrate_beta`. Affected: the `nsm_bayes.inference.bootstrap` module docstring, `models/general/posterior.py` (module docstring and a section comment), and `models/conjugate/conj_posterior.py` (the `See Also` block and a section comment).
- `nsm_bayes.inference.beta_bo_calibration` now imports `gpytorch`: the module used `gpytorch` (in the `CoverageGP` class body) without ever importing it, so importing the module raised `NameError` (and `tests/test_units.py::test_optimize_beta_bo_rejects_bad_inputs` failed).

### Fixed

- `TurinSimulator.simulate_channel` now accepts a single `(4,)` log-parameter vector or a batched `(n, 4)` tensor: the parameters are unpacked with `unbind` on the last dimension instead of flat Python unpacking, which raised `ValueError` for batched input (breaking `generate_training_data`, where each receiver now uses its own prior draw); a lone row is broadcast across all receivers. Also fixed `generate_contaminated_data`'s `simulate_channel` call, which passed the keyword `N=` instead of `n_obs=`.
- `experiments/turin.generate_data` now unpacks `generate_contaminated_data`'s `(x_obs_mis, outlier_indices)` return instead of storing the tuple as `x_obs_mis` (which crashed `GeneralPosterior`); the indices are kept in the `outlier_indices` extra, saved as a new per-repetition artifact.
- **Behaviour change:** `GeneralModel.fit` and `GeneralModel.load_checkpoint` now freeze the estimator's parameters (`requires_grad_(False)`, matching `EnergyBasedModel.fit`/`load_checkpoint`). Previously the trained flow kept `requires_grad=True` parameters, so every log-density evaluation of the slice sampler (the base-pool draw in `prepare_calibration` and the final `sample(beta)` in `run_normflow_methods`, both running under default grad mode) built a full autograd graph through the flow — including the forward-over-reverse Hessian graph of the score-matching loss — that was never used, and `compute_theta_hat_true`'s `loss.backward()` additionally computed and accumulated gradients for the flow parameters that the Adam loop (which updates only `theta`) never read. Forward values are unchanged, so results for a fixed seed are bit-identical; the slice-sampler evaluations and the `theta_hat` minimisation are faster and use less memory. Gradients with respect to `theta` (the conditioning input, used by `compute_theta_hat_true`) are unaffected by the freeze.
- `EnergyBasedModel.load_checkpoint` now freezes the model it *returns*: when the checkpoint's dimensions differ from the instance's, a fresh model is built and loaded, but only the original instance was frozen, so the returned model still had `requires_grad=True` parameters. In-repo callers always load into a same-dimension model, where the two coincide, so results are unchanged.
- `tests/test_run_sir_undercounting.py::test_sir_uc_undercounting_is_one_sided` was flaky: the un-contaminated-row check compared the clean and corrupted summaries with a single `atol=0.05` on all three columns, but the two `summary()` calls add independent noise of scale `1/(T_sir - 1)` (~0.026 for the tiny `T_sir=40` config) to the peak-time column, which aggregates to ~0.037 and can exceed 0.05 (observed 0.087 at a 2σ draw). The peak-time column is now compared with its own noise scale (`10/(T_sir - 1)`, ~1 sigma of the aggregate) while the attack-rate and peak-height columns keep the `0.05` tolerance. Test-only change; results are unaffected.

### Changed

- **Behaviour change:** `Posterior.estimate_coverage` (both `GeneralPosterior` and `ConjugatePosterior`) now returns the 3-tuple `(coverage, ess_mean, pool_size)` instead of the scalar coverage, and the calibration history gains an `"ess"` key: the SA loop records the mean effective sample size at every iteration (for the conjugate method this is `inf`, as it has no MCMC pool), and `run_grid_search` / `grid_start` record one ESS per evaluated grid point (so `calibrate_beta`'s `grid` history also carries it). The ESS values are diagnostic only — they do not change the coverage estimates, the pool-refresh logic or the calibrated `beta`, so results for a fixed seed are bit-identical apart from the extra history entries in the `gpc_history` artifact.
- **Behaviour change:** the summary noise of `SIRSimulator.summary(add_noise=True)` is now per-column on each summary's native scale — standard deviation `1/N` for the attack rate and peak height, `1/(T - 1)` for the peak time — instead of `1/N` for all three columns. Every `add_noise=True` call draws different noise for a fixed seed (training `x_sim` in `sir`/`sir_undercounting`, and the `x_obs` summaries, which also use the default `add_noise=True`); `add_noise=False` (e.g. `generate_contaminated_data`) is unchanged.
- **Breaking API change / Behaviour change:** `SIRSimulator.generate_training_data` now returns `(theta, x_sim)` with the summary computed internally (noise of scale `1/N` always added), and `SIRSimulator.generate_contaminated_data` returns `(x_obs_mis, is_contam)` where `x_obs_mis` is the summary without any noise (raw `(n_obs, T)` incidence is no longer exposed). The experiments and example notebooks were updated; for a fixed seed, `theta`, `x_sim` and `x_obs` are bit-identical to before, while `x_obs_mis` for `sir` and `sir_undercounting` changes (it is now noise-free, and the RNG stream no longer consumes the summary-noise draw).
- **Breaking API change:** the experiment modules' uniform interface dropped its unused arguments: `build_problem(cfg)` now returns `(sim, prior, theta_true)` (the `d_x` return value only ever fed `generate_data`) and `generate_data(sim, theta_true, cfg)` (the `prior` and `d_x` parameters were unused by every experiment). All four experiments keep the same two-function interface; `common.run_experiment`, the `test_data` bundle builders and the tests were updated in the same change (the bundle's `d_x` now comes from `cfg.d_x`, the same value). No RNG calls changed, so results are bit-identical for a fixed seed.
- **Breaking API change:** `nsm_bayes.inference.general.calibrate.calibrate_beta` and `nsm_bayes.inference.conjugate.calibrate_beta.calibrate_beta_gpc` were merged into `nsm_bayes.inference.beta_calibration_loop.calibrate_beta` and the two old modules deleted. The unified signature is `calibrate_beta(posterior, x_obs=None, beta_init=0.01, alpha=0.05, B=200, n_iterations=10, step_schedule=..., max_log_step=0.25, beta_min=0.01, ess_threshold=0.3)`: `beta_base`/`initial_beta` became `beta_init`, `target_coverage` became `alpha` (target `1 - alpha`), `num_iterations`/`T` unified to `n_iterations`, `num_bootstraps`/`B` unified to `B`, and `x_obs` is required for the conjugate posterior. The base MCMC pool is not a parameter: `prepare_calibration` draws it at `beta_init` inside the calibration loop and caches it on the posterior's `theta_samples` attribute (the conjugate method never draws one). Importing either old function fails.
- **Breaking API change:** the multivariate slice sampler moved from `nsm_bayes.inference.general.slice_sampler` to `nsm_bayes.inference.slice_sampler` (the `inference.general` and `inference.conjugate` subpackages are gone). Results are unaffected.
- **Behaviour change:** the base MCMC pool for the general method is now drawn by `GeneralPosterior.prepare_calibration` (at `beta_init`) inside the `cost_sm_mcmc` block instead of by `run_normflow_methods` before calling `calibrate_beta`. It is the same `GeneralPosterior.sample(beta_base_general)` call on the same RNG state, so the drawn pool and all downstream results for a fixed seed are identical; only the wall-clock timing attributed to `cost_sm_mcmc` (now including the base draw) and the fact that the pool is cached on the posterior's `theta_samples` attribute differ.
- **Behaviour change:** the general method's ESS refresh happens *inside* the per-iteration coverage call instead of after the beta update of the same iteration. The refreshed pool therefore feeds the *next* iteration's coverage estimate, not the one that triggered the refresh; the refresh itself (trigger threshold, new-pool drawing at the SA-updated beta) is unchanged, and in practice triggers at most once, so results for a fixed seed are expected to be numerically identical or nearly so.
- **Behaviour change:** the conjugate calibrator no longer prints its per-iteration progress and final beta (the `tqdm` bar is gone); the returned `(beta, history)` are unaffected.
- Example notebooks updated to the new API: `sir_conjugate.ipynb` and `fromdata.ipynb` (conjugate: `calibrate_beta(posterior, beta_init=..., alpha=..., n_iterations=..., B=..., x_obs=...)`) and `gnk_general.ipynb` (general: `calibrate_beta(posterior, beta_init=..., ...)`).

### Changed

- `EnergyBasedModel` can now be built from a checkpoint file alone, without data or config: `EnergyBasedModel(checkpoint=path)` reads `d_x`, `d_theta` and `hidden_dim` from the saved weight shapes and the dtype of the saved weights, then loads the networks and standardisers written by `save_checkpoint`. Dimensions passed together with a checkpoint must match it (a `ValueError` naming the dimension is raised otherwise); `d_x`/`d_theta` remain required (and `hidden_dim` still defaults to 128) when no checkpoint is given. New read-only properties `d_x`, `d_theta` and `hidden_dim` expose the dimensions derived from the modules. The checkpoint format (`conjugate_nets_<rep>.pt`) and every existing call (`EnergyBasedModel(d_x=..., d_theta=..., hidden_dim=...)`, `load_checkpoint`) are unchanged, and results are bit-identical.
- `nsm_bayes.utils.set_seed(seed)`: seeds `numpy` and `torch` in one call; experiment scripts now use it with a per-experiment `seed_offset` config value (gnk: 1, sir / sir_undercounting / turin: 123).
- `sigma_inverse` now accepts a `jitter` argument (default `1e-6`) and returns the inverse of `Sigma + jitter * I`; its broken error message (which referenced undefined names) was fixed.
- `gpc.weighted_mean_cov` gained a `jitter` argument (default `1e-6`).
- Small division/log safety epsilons are now named module constants in `gpc.py`, `method.py`, `turin.py`, `sir.py` and `add_noise.py`.

### Changed

- **Breaking API change:** the `ConjugateModel` class in `nsm_bayes.models.conjugate` is renamed `EnergyBasedModel`. All in-repo consumers are updated (`experiments/common.py`, `tests/`, `examples/sir_conjugate.ipynb`, `examples/pickle_simulator.ipynb`); the module path (`nsm_bayes.models.conjugate.conj_model`), the export name change in `nsm_bayes.models.conjugate.__init__` and any external code importing `ConjugateModel` must follow. Results are unaffected; checkpoints (`conjugate_nets_<rep>.pt`) store state dicts only and load unchanged via `EnergyBasedModel.load_checkpoint`.
- Split the monolithic `nsm_bayes.method` module into focused modules and re-pointed all consumers: `robust_mean_cov`, `sample_mean_and_covariance` and `estimate_stats` live in `nsm_bayes.utils.statistics`; `safe_cholesky`, `sigma_inverse`, `sample_mean_and_covariance`, `set_seed` and the `jacobian*`/`hessian*` helpers live in `nsm_bayes.utils.utils`; the conjugate posterior (`compute_posterior_conjugate`, `get_div_term_single`, ...) lives in `nsm_bayes.models.conjugate.conj_posterior`; the multivariate slice sampler lives in `nsm_bayes.slice_sampler`; and general-posterior sampling lives in `nsm_bayes.posterior`. `nsm_bayes.method` now only holds the general score-matching losses and `ScoreMatchingLogPosterior`. ### Fixed

- `EnergyBasedModel.save_checkpoint` call site in `run_conjugate_method` still passed `(cfg, save_dir, rep)` after the signature changed to `(save_file)`; it now passes the full path `save_dir / f"conjugate_nets_{rep}.pt"`. The `"config"` key is no longer written to (or asserted in) checkpoints, matching the documented contents (state dicts + standardisers only).

- Added `__init__.py` to `nsm_bayes.simulators`, `nsm_bayes.simulators.benchmark_simulators`, `nsm_bayes.viz` and `nsm_bayes.inference.conjugate`. They were namespace packages, so a non-editable `pip install .` (setuptools `find_packages`) silently omitted them from the wheel; editable installs were unaffected.

- **Behaviour change:** `GeneralPosterior._per_x_sm_loss` called the raw estimator as `self.flow.estimator.log_prob(xi, theta).reshape(1)` with `xi` of shape `(d_x,)` and a commented-out fallback. Under sbi 0.27 the flow's `log_prob` interprets the leading dimension as `sample_dim` (`(sample_dim, batch_dim)`), so a 1-D `xi` was mis-read as `sample_dim=d_x` and the broadcast against the 100-condition batch produced a `(d_x, 100)` result (400 elements for g-and-k, `d_x=4`) that the `.reshape(1)` could not flatten, raising `RuntimeError: shape '[100, 1]' is invalid for input of size 400` in `GeneralPosterior.sample` and `calibrate_beta`. The call now goes through `GeneralModel.log_prob(xi, theta_vec=theta)`, which batches `xi` to `(1, d_x)` so the estimator sees one input row per condition; the `-1e10` clamp of `GeneralModel.log_prob` also now applies to the score-matching loss, matching the NLE baseline.
- Removed broken dead imports (`compute_posterior_case1`) that made `scripts/normflow/run_gnk.py` and `scripts/normflow/run_sir_undercounting.py` fail at import time.
- `tests/test_run_gnk.py` loads the checkpoint written by `save_checkpoint` (`conjugate_nets_*.pt`).
