# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Added

- `nsm_bayes.inference.beta_bo_calibration.optimize_beta_bo(betas, coverages, target_coverage=..., beta_min=...)`: Bayesian-optimisation beta calibration via a GP on a coverage grid. Fits a `Matern`-kernel `GaussianProcessRegressor` to pre-computed `(log beta, coverage)` pairs and returns the scalar `beta` where the GP mean crosses the target coverage (clamped to `beta_min`). Unit-tested in `tests/test_units.py` (5 tests: crossing recovery, no-crossing fallback, `beta_min` floor, input validation, determinism).
- `nsm_bayes.inference.beta_calibration_loop.calibrate_beta(posterior, beta_init, ...)`: a single unified beta calibrator that drives the shared stochastic-approximation loop over `log beta` for both methods. The method-specific work moved into the posterior classes, which now both expose `prepare_calibration(...)` (caches the NSM point estimate `theta_hat`; for the general method also draws and caches the base MCMC pool at `beta_init` and its per-observation losses) and `estimate_coverage(...)` (importance-reweighted coverage with the ESS-gated pool refresh for :class:`GeneralPosterior`; closed-form bootstrap coverage for :class:`ConjugatePosterior`). Both share one flat signature — each class ignores the arguments its method does not need. `run_normflow_methods` and `run_conjugate_method` now call this single entry point.
- The `on_update` callback of the shared SA loop is gone; the ESS-gated refresh now happens inside `GeneralPosterior.estimate_coverage` when the mean effective sample size falls below `ess_threshold * M` (the pool is redrawn at the SA-updated `beta`, computed from the just-estimated coverage with the loop's step `k_t = 10 / (t + 10)`).
- `ConjugatePosterior` now prints nothing during calibration: the `tqdm` bar and the per-iteration / final prints of the old `calibrate_beta_gpc` were dropped (logging goes through `logging.getLogger` instead).

### Fixed

- **Behaviour change:** `GeneralModel.fit` and `GeneralModel.load_checkpoint` now freeze the estimator's parameters (`requires_grad_(False)`, matching `EnergyBasedModel.fit`/`load_checkpoint`). Previously the trained flow kept `requires_grad=True` parameters, so every log-density evaluation of the slice sampler (the base-pool draw in `prepare_calibration` and the final `sample(beta)` in `run_normflow_methods`, both running under default grad mode) built a full autograd graph through the flow — including the forward-over-reverse Hessian graph of the score-matching loss — that was never used, and `compute_theta_hat_true`'s `loss.backward()` additionally computed and accumulated gradients for the flow parameters that the Adam loop (which updates only `theta`) never read. Forward values are unchanged, so results for a fixed seed are bit-identical; the slice-sampler evaluations and the `theta_hat` minimisation are faster and use less memory. Gradients with respect to `theta` (the conditioning input, used by `compute_theta_hat_true`) are unaffected by the freeze.
- `EnergyBasedModel.load_checkpoint` now freezes the model it *returns*: when the checkpoint's dimensions differ from the instance's, a fresh model is built and loaded, but only the original instance was frozen, so the returned model still had `requires_grad=True` parameters. In-repo callers always load into a same-dimension model, where the two coincide, so results are unchanged.
- `tests/test_run_sir_undercounting.py::test_sir_uc_undercounting_is_one_sided` was flaky: the un-contaminated-row check compared the clean and corrupted summaries with a single `atol=0.05` on all three columns, but the two `summary()` calls add independent noise of scale `1/(T_sir - 1)` (~0.026 for the tiny `T_sir=40` config) to the peak-time column, which aggregates to ~0.037 and can exceed 0.05 (observed 0.087 at a 2σ draw). The peak-time column is now compared with its own noise scale (`10/(T_sir - 1)`, ~1 sigma of the aggregate) while the attack-rate and peak-height columns keep the `0.05` tolerance. Test-only change; results are unaffected.

### Changed

- **Behaviour change:** `Posterior.estimate_coverage` (both `GeneralPosterior` and `ConjugatePosterior`) now returns the 3-tuple `(coverage, ess_mean, pool_size)` instead of the scalar coverage, and the calibration history gains an `"ess"` key: the SA loop records the mean effective sample size at every iteration (for the conjugate method this is `inf`, as it has no MCMC pool), and `run_grid_search` / `grid_start` record one ESS per evaluated grid point (so `calibrate_beta`'s `grid` history also carries it). The ESS values are diagnostic only — they do not change the coverage estimates, the pool-refresh logic or the calibrated `beta`, so results for a fixed seed are bit-identical apart from the extra history entries in the `gpc_history` artifact.
- **Behaviour change:** the summary noise of `SIRSimulator.summary(add_noise=True)` is now per-column on each summary's native scale — standard deviation `1/N` for the attack rate and peak height, `1/(T - 1)` for the peak time — instead of `1/N` for all three columns. Every `add_noise=True` call draws different noise for a fixed seed (training `x_sim` in `sir`/`sir_undercounting`, and the `x_obs` summaries, which also use the default `add_noise=True`); `add_noise=False` (e.g. `generate_contaminated_data`) is unchanged.
- **Breaking API change / Behaviour change:** `SIRSimulator.generate_training_data` now returns `(theta, x_sim)` with the summary computed internally (noise of scale `1/N` always added), and `SIRSimulator.generate_contaminated_data` returns `(x_obs_mis, is_contam)` where `x_obs_mis` is the summary without any noise (raw `(n_obs, T)` incidence is no longer exposed). The experiments and example notebooks were updated; for a fixed seed, `theta`, `x_sim` and `x_obs` are bit-identical to before, while `x_obs_mis` for `sir` and `sir_undercounting` changes (it is now noise-free, and the RNG stream no longer consumes the summary-noise draw).
- **Breaking API change:** the experiment modules' uniform interface dropped its unused arguments: `build_problem(cfg)` now returns `(sim, prior, theta_true)` (the `d_x` return value only ever fed `generate_data`) and `generate_data(sim, theta_true, cfg)` (the `prior` and `d_x` parameters were unused by every experiment). All four experiments keep the same two-function interface; `common.run_experiment`, the `test_data` bundle builders and the tests were updated in the same change (the bundle's `d_x` now comes from `cfg.d_x`, the same value). No RNG calls changed, so results are bit-identical for a fixed seed.
- **Breaking API change:** `nsm_bayes.inference.general.calibrate.calibrate_beta` and `nsm_bayes.inference.conjugate.calibrate_beta.calibrate_beta_gpc` were merged into `nsm_bayes.inference.beta_calibration_loop.calibrate_beta` and the two old modules deleted. The unified signature is `calibrate_beta(posterior, x_obs=None, beta_init=0.01, alpha=0.05, B=200, n_iterations=10, step_schedule=..., max_log_step=0.25, beta_min=0.01, ess_threshold=0.3)`: `beta_base`/`initial_beta` became `beta_init`, `target_coverage` became `alpha` (target `1 - alpha`), `num_iterations`/`T` unified to `n_iterations`, `num_bootstraps`/`B` unified to `B`, and `x_obs` is required for the conjugate posterior. The base MCMC pool is not a parameter: `prepare_calibration` draws it at `beta_init` inside the calibration loop and caches it on the posterior's `theta_samples` attribute (the conjugate method never draws one). Importing either old function fails.
- **Breaking API change:** the multivariate slice sampler moved from `nsm_bayes.inference.general.slice_sampler` to `nsm_bayes.inference.slice_sampler` (the `inference.general` and `inference.conjugate` subpackages are gone). Results are unaffected.
- **Behaviour change:** the base MCMC pool for the general method is now drawn by `GeneralPosterior.prepare_calibration` (at `beta_init`) inside the `cost_sm_mcmc` block instead of by `run_normflow_methods` before calling `calibrate_beta`. It is the same `GeneralPosterior.sample(beta_base_general)` call on the same RNG state, so the drawn pool and all downstream results for a fixed seed are identical; only the wall-clock timing attributed to `cost_sm_mcmc` (now including the base draw) and the fact that the pool is cached on the posterior's `theta_samples` attribute differ.
- **Behaviour change:** the general method's ESS refresh happens *inside* the per-iteration coverage call instead of after the beta update of the same iteration. The refreshed pool therefore feeds the *next* iteration's coverage estimate, not the one that triggered the refresh; the refresh itself (trigger threshold, new-pool drawing at the SA-updated beta) is unchanged, and in practice triggers at most once, so results for a fixed seed are expected to be numerically identical or nearly so.
- **Behaviour change:** the conjugate calibrator no longer prints its per-iteration progress and final beta (the `tqdm` bar is gone); the returned `(beta, history)` are unaffected.
- Example notebooks updated to the new API: `sir_conjugate.ipynb` and `fromdata.ipynb` (conjugate: `calibrate_beta(posterior, beta_init=..., alpha=..., n_iterations=..., B=..., x_obs=...)`) and `gnk_general.ipynb` (general: `calibrate_beta(posterior, beta_init=..., ...)`).

### Removed

- The `rm` (Robbins-Monro) beta-calibration update rule: `nsm_bayes.inference.beta_update_rules.step_rm`, the `BetaState.slope` field (read only by `step_rm`) and the `calibrate_beta(..., method="rm", rm_slope=...)` path are gone. `calibrate_beta` now dispatches to `gpc`, `bisect` and `grid` only; the grid search still returns the coverage slope for history, but no rule consumes it.
- `nsm_bayes.inference.general.calibrate` and `nsm_bayes.inference.conjugate.calibrate_beta` (including the unused `calibrate_beta_grid`) — superseded by `nsm_bayes.inference.beta_calibration_loop.calibrate_beta`.
- The `theta_samples_base` parameter of `prepare_calibration` / `estimate_coverage` (unused by every caller) and the `theta_samples_base()` methods on both posterior classes (the cached pool is read from the `theta_samples` attribute).
- The `sample_mean_and_covariance` re-export from `nsm_bayes.utils` (the function itself remains in `nsm_bayes.utils.statistics`).
- The `set_seed` re-export from `nsm_bayes.experiments.common.__all__` (the function remains in `nsm_bayes.utils`).

### Changed

- `EnergyBasedModel` can now be built from a checkpoint file alone, without data or config: `EnergyBasedModel(checkpoint=path)` reads `d_x`, `d_theta` and `hidden_dim` from the saved weight shapes and the dtype of the saved weights, then loads the networks and standardisers written by `save_checkpoint`. Dimensions passed together with a checkpoint must match it (a `ValueError` naming the dimension is raised otherwise); `d_x`/`d_theta` remain required (and `hidden_dim` still defaults to 128) when no checkpoint is given. New read-only properties `d_x`, `d_theta` and `hidden_dim` expose the dimensions derived from the modules. The checkpoint format (`conjugate_nets_<rep>.pt`) and every existing call (`EnergyBasedModel(d_x=..., d_theta=..., hidden_dim=...)`, `load_checkpoint`) are unchanged, and results are bit-identical.
- `nsm_bayes.utils.set_seed(seed)`: seeds `numpy` and `torch` in one call; experiment scripts now use it with a per-experiment `seed_offset` config value (gnk: 1, sir / sir_undercounting / turin: 123).
- `sigma_inverse` now accepts a `jitter` argument (default `1e-6`) and returns the inverse of `Sigma + jitter * I`; its broken error message (which referenced undefined names) was fixed.
- `gpc.weighted_mean_cov` gained a `jitter` argument (default `1e-6`).
- Small division/log safety epsilons are now named module constants in `gpc.py`, `method.py`, `turin.py`, `sir.py` and `add_noise.py`.

### Changed

- **Breaking API change:** the `ConjugateModel` class in `nsm_bayes.models.conjugate` is renamed `EnergyBasedModel`. All in-repo consumers are updated (`experiments/common.py`, `tests/`, `examples/sir_conjugate.ipynb`, `examples/pickle_simulator.ipynb`); the module path (`nsm_bayes.models.conjugate.conj_model`), the export name change in `nsm_bayes.models.conjugate.__init__` and any external code importing `ConjugateModel` must follow. Results are unaffected; checkpoints (`conjugate_nets_<rep>.pt`) store state dicts only and load unchanged via `EnergyBasedModel.load_checkpoint`.
- Split the monolithic `nsm_bayes.method` module into focused modules and re-pointed all consumers: `robust_mean_cov`, `sample_mean_and_covariance` and `estimate_stats` live in `nsm_bayes.utils.statistics`; `safe_cholesky`, `sigma_inverse`, `sample_mean_and_covariance`, `set_seed` and the `jacobian*`/`hessian*` helpers live in `nsm_bayes.utils.utils`; the conjugate posterior (`compute_posterior_conjugate`, `get_div_term_single`, ...) lives in `nsm_bayes.models.conjugate.conj_posterior`; the multivariate slice sampler lives in `nsm_bayes.slice_sampler`; and general-posterior sampling lives in `nsm_bayes.posterior`. `nsm_bayes.method` now only holds the general score-matching losses and `ScoreMatchingLogPosterior`. Importing `sigma_inverse`, `robust_mean_cov` or `calculate_training_loss` from `nsm_bayes.method` no longer works.
- **Behaviour change 1:** `ConjugateModel.calibrated_posterior` now inverts the data covariance through `sigma_inverse`, whose default adds `1e-6 * I`. The original repo used `inv(S + 1e-6 I)` there, so this restores the original behaviour.
- **Behaviour change 2:** the default step-size schedule of `gpc.calibrate_beta_gpc` changed from `5 / (t + 10)` to `10 / (t + 10)`, matching what every experiment script always overrode it with; the scripts no longer pass the override.
- `c` (IMQ weight scale) is now a default argument (`c: float = 1.0`) of `gpc.calibrate_beta` and `gpc.calibrate_beta_gpc`; the hard-coded `c_obs = 1.` / `c_boot = 1.` inside `calibrate_beta_gpc` were removed. Experiment scripts no longer define or pass `c = 1.`.
- The inline `torch.linalg.inv(S + 1e-6 * torch.eye(...))` calls in the scripts, `gpc.py` and the example notebooks (`sir_conjugate.ipynb`, `gnk_general.ipynb`) were replaced with `sigma_inverse(S)`.
- The dead `step_schedule=lambda t: 10.0/(t+10.)` and `learning_rate_fn=lambda t: 10.0/(t+10.)` keyword overrides in the scripts were removed; they were identical to the functions' defaults, so results are unchanged.
- The test-data bundle builders `examples/experimental/make_test_data_{gnk,gnk_normflow,sir}.py` moved to `src/nsm_bayes/experiments/test_data/` and are now run as modules from the repo root: `python -m nsm_bayes.experiments.test_data.make_test_data_gnk` (likewise `..._gnk_normflow`, `..._sir`). Bundles are still written to `examples/experimental/data/`, so notebook data paths are unchanged; notebook run instructions were updated. The duplicated logic between the three scripts (paths, config loading, seed+generate preamble, bundle assembly, pickle saving, argparse `main`, and the SIR constants that lived in the GNK script) now lives in `nsm_bayes.experiments.test_data.common`; each script keeps only its sizes, model and config keys. Bundles keep the same keys and data for a fixed seed, except ``meta`` no longer records ``train_secs``.
- `from __future__ import annotations` was removed from every module: nothing in the repo needed it (no forward references, no `TYPE_CHECKING` imports, Python ≥ 3.10); the corresponding AGENTS.md style rule was dropped. This unmasked an invalid annotation, `timed(...) -> Generator[None]` in `experiments/common.py` (only legal because it was never evaluated), which is now `Generator[None, None, None]`. Results are unchanged.

### Removed

- `GNK_NOISE_STD` and the `outlier_noise_std` bundle `meta` entry in the GNK bundle builder: the Gaussian outlier noise was documented but never actually applied to `x_obs_mis`.
- `random.seed(seed)` from `nsm_bayes.utils.set_seed`: nothing in `src/`, `scripts/`, `tests/` or `examples/` consumes the stdlib `random` module, so seeding it changed nothing. Results are bit-identical for a fixed seed.

- Dead code deleted (no behaviour change for any experiment; results are bit-identical for a fixed seed): `calculate_training_loss1` (`nsm_bayes.models.conjugate.conj_train`), `add_student_t_noise`, the free functions `simulate_contaminated_dataset` and `apply_undercounting_trajectory` (`nsm_bayes.simulators.add_noise`, both duplicates of `SIRSimulator` methods that were never called), `GandKSimulator.generate_observed_data`, `ConjugatePosterior.precompute`, the Turin `simulate(output="data")` branch with its `Ns`/`epsilon`/noise-only-receiver machinery, and the SIR negative-binomial / 5-parameter branch (`obs_model`, `log phi`; the `SIRSimulator(obs_model=...)` keyword is gone — `experiments/sir.py`, `tests/test_run_sir_undercounting_conjugate.py` and `examples/sir_conjugate.ipynb` updated). Also removed: the never-read config keys `n_obs_ref` and `sr_num_samples_per_param*`, `configs/__init__.py`, and the stale `[tool.setuptools.package-data]` entry in `pyproject.toml` (it pointed at a `config/` directory that does not exist).
- `joblib` dependency: the slice sampler ran its chains through `joblib.Parallel(n_jobs=1)` and no caller ever overrode `n_jobs`, so `run_multivariate_slice_sampler_tuned` now loops over chains plainly and its `n_jobs` keyword is gone. Results are bit-identical for a fixed seed.
- The `GNKSimulator` alias of `GandKSimulator` in `nsm_bayes.simulators.benchmark_simulators.simulators`; import `GandKSimulator` instead (`tests/test_run_gnk_conjugate.py` updated).
- The unused `jitter` argument of `sigma_inverse` (it was never applied to the matrix, so behaviour is unchanged).
- Stale `SIRSimulator` docstrings: `generate_training_data` documented three return values but returns two (`theta`, `y`); `summary`'s `y` argument no longer has a `None` default.

### Fixed

- `EnergyBasedModel.save_checkpoint` call site in `run_conjugate_method` still passed `(cfg, save_dir, rep)` after the signature changed to `(save_file)`; it now passes the full path `save_dir / f"conjugate_nets_{rep}.pt"`. The `"config"` key is no longer written to (or asserted in) checkpoints, matching the documented contents (state dicts + standardisers only).

- Added `__init__.py` to `nsm_bayes.simulators`, `nsm_bayes.simulators.benchmark_simulators`, `nsm_bayes.viz` and `nsm_bayes.inference.conjugate`. They were namespace packages, so a non-editable `pip install .` (setuptools `find_packages`) silently omitted them from the wheel; editable installs were unaffected.

- **Behaviour change:** `GeneralPosterior._per_x_sm_loss` called the raw estimator as `self.flow.estimator.log_prob(xi, theta).reshape(1)` with `xi` of shape `(d_x,)` and a commented-out fallback. Under sbi 0.27 the flow's `log_prob` interprets the leading dimension as `sample_dim` (`(sample_dim, batch_dim)`), so a 1-D `xi` was mis-read as `sample_dim=d_x` and the broadcast against the 100-condition batch produced a `(d_x, 100)` result (400 elements for g-and-k, `d_x=4`) that the `.reshape(1)` could not flatten, raising `RuntimeError: shape '[100, 1]' is invalid for input of size 400` in `GeneralPosterior.sample` and `calibrate_beta`. The call now goes through `GeneralModel.log_prob(xi, theta_vec=theta)`, which batches `xi` to `(1, d_x)` so the estimator sees one input row per condition; the `-1e10` clamp of `GeneralModel.log_prob` also now applies to the score-matching loss, matching the NLE baseline.
- Removed broken dead imports (`compute_posterior_case1`) that made `scripts/normflow/run_gnk.py` and `scripts/normflow/run_sir_undercounting.py` fail at import time.
- `tests/test_run_gnk.py` loads the checkpoint written by `save_checkpoint` (`conjugate_nets_*.pt`).
